Progressive reuse without a seventh session

Existing session Repository action before leaving
TD1 Initialize the skeleton; freeze data hash, time boundary, seasonal-naive baseline and first TS-01 pointers.
TD2 Add rolling-origin model comparison, information-boundary audit, failure period and configuration paths.
TD3 Freeze MDP/reward contract and random/reorder baselines; start RL-01.
TD4 Add frozen Q-table, learning configuration and independent development evaluation.
TDo1 Freeze the forecasting release, final 28-day forecast CSV and controlled handoff.
TDo2 Freeze the RL safety release and handoff; complete OPS-01.

These are evidence-capture actions inside the scheduled work, not extra tasks. The final quick replay still samples exactly one frozen release command per strand; it does not rerun all six notebooks.

Required release

  • Forecasting release: TD1 time/baseline evidence, TD2 rolling-origin model evidence, TDo1 release evidence and the protected-horizon receipt.
  • RL policy release: TD3 environment/baseline evidence, TD4 frozen policy evidence, TDo2 safety evidence and the controlled-batch aggregate/receipt.
  • Operational/safety synthesis: a conditional go/hold/no-go decision, named fallback and refusal boundary, derived from the two releases.

The synthesis is not an integration experiment. Unless separate end-to-end evidence exists outside this module, state explicitly that the forecast was not used as an RL observation and that joint controller performance was not tested.

Quick replay

Run from the repository root:

python scripts/quick_replay.py --config configs/replay.yaml

The runner accepts exactly two commands, forecasting then reinforcement-learning. It confines paths to the repository, rejects obvious training/tuning tokens, hashes scripts/configuration/data, snapshots outputs, requires newly created or refreshed regular files, and checks that declared inputs did not change. It deletes any older success receipt at attempt start. A success receipt is emitted only after both commands pass; otherwise the failed status is authoritative.

The public replay never recreates protected targets or hidden RL seeds. Cite the two instructor-issued receipts separately in submission.yaml and claims_evidence.csv.
